### 六、散列查找（哈希查找）(Hash Search)

*   **思想**：根据关键字 `key`，通过散列函数 `H(key)` 直接计算出其存储地址。
*   **示例**：`H(key) = key % 7`。将关键字 `[5, 3, 8, 1, 12]` 存入表长 `m=7` 的散列表中。
    *   `5%7=5` -> 存入地址5。
    *   `3%7=3` -> 存入地址3。
    *   `8%7=1` -> 存入地址1。
    *   `1%7=1` -> **冲突**！使用线性探测法 `H₁=(1+1)%7=2` -> 存入地址2。
    *   查找 `1`：`H(1)=1`，比较发现地址1是 `8`，不等于 `1`，继续线性探测下一个地址 `2`，找到 `1`。
*   **性能指标**：
    *   **时间复杂度**：
        *   最好情况（无冲突）：$O(1)$。
        *   平均情况：取决于**处理冲突的方法**和**装填因子 α**（α = 表中记录数n / 表长m）。α越大，冲突可能性越大，ASL越大。
    *   **空间复杂度**：$O(n)$。需要预先分配一个较大的数组。
    *   **特点**：
        *   追求平均时间复杂度为 $O(1)$ 的查找效率。
        *   **“以空间换时间”** 的典型代表。
    *   **稳定性**：**不稳定**。散列函数将记录完全打散，原始顺序荡然无存。

### 七、综合对比表

| 查找算法 | 时间复杂度(平均/最坏) | 空间复杂度 | 存储结构要求 | 有序性要求 | 稳定性 | 主要特点与适用场景 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **顺序查找** | $O(n)$ / $O(n)$ | $O(1)$ | 顺序/链式 | 无要求 | **稳定** | 通用性强，效率低，适用于小规模或无序数据。 |
| **折半查找** | $O(log n)$ / $O(log n)$ | $O(1)$ | **顺序存储** | **必须有序** | **稳定** | 效率高，适用于**静态**查找表，不能用于链式存储。 |
| **分块查找** | $O(log(m)+n/m)$¹ / $O(n)$ | $O(n)$ | 顺序/链式 | 块间有序 | **稳定** | 是顺序和折半的折中，适用于动态变化且分块有序的表。 |
| **二叉排序树** | $O(log n)$ / $O(n)$ | $O(n)$ | 链式 | 中序有序 | 不稳定 | **动态查找表**，插入删除方便，但可能退化。 |
| **平衡二叉树** | $O(log n)$ / $O(log n)$ | $O(n)$ | 链式 | 中序有序 | 不稳定 | **动态查找表**，通过旋转避免退化，维护平衡有开销。 |
| **散列查找** | **$O(1)$** / $O(n)$ | $O(n)$ | 顺序 | 无要求 | 不稳定 | **“以空间换时间”**，追求极高平均效率，需处理冲突。 |

*¹ m为分块数，n/m为块内平均长度。*

**总结与软考考点**：
1.  **必考手工模拟**：**折半查找**的过程、**BST**的查找/插入/删除、**AVL**的旋转调整、**散列表**的构造和冲突解决。
2.  **掌握ASL计算**：特别是二分查找判定树和散列表的ASL计算。
3.  **理解适用场景**：能根据问题描述选择合适的查找算法，并说明理由（例如，静态有序用折半，动态查找用BST/AVL，追求极致速度用散列）。
